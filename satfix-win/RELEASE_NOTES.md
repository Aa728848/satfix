# 发布说明（Release notes）

这个文件是**发布说明的唯一来源**：`tools/package_release.ps1` 会从它抽出对应版本的
那一节，作为 GitHub Release 的正文。改说明改这里，不要在 GitHub 网页上直接改 ——
否则下次发布时会被覆盖，而且没有版本记录。

## 约定

- 每个版本一节，标题格式 `## v<版本>`，与清单里的 `version` 一致。
- 最新的写在**最上面**。
- 发布流程见 `README.md` 的「发布与自动更新」一节。

## v0.3.1

补了一个上版漏掉的洞：**舰船设计界面里显示的基础船体值**。

### 修了什么

- **设计界面「船体值」显示成天文数字的负数**。有些 mod 在 `common/ship_sizes/`
  里把 `max_hitpoints` 写得很夸张，游戏读到这种数会算崩，设计界面就会显示成
  一长串负号数字（比如 `-84467440737095.51`），看着就像这船没血。
  现在这种数会被改成游戏能表示的最大值，也就是那个「92 万亿」。

  这个和上版修的护盾、伤害是同一类问题，但**触发的地方不一样**：护盾那条是在
  算上限的时候崩的，这条是在**读 mod 文件的时候**就已经崩了。所以上版的修复碰不到它。

  实测对照（同一个存档、同一个 mod，只切换插件开关）：

  | | 设计界面显示 |
  |---|---|
  | 不开插件 | `-84467440737095.51` |
  | 开插件 | `92233720368547.75` |

  > 说句实话：**别人的 mod 要真的把 `max_hitpoints` 写到 92 万亿以上才会触发**。
  > 我扫了自己这套播放集里的 22 个 mod，最大的才 5 亿，离出问题还差得很远。
  > 所以这更像是「提前把洞补上」，你要是不装那种特别离谱的 mod，可能一直也用不到。

- 上版说过「船体那个数我没亲眼见过它溢出」，**现在见过了** —— 就是上面这次测试。
  当时是专门造了个测试 mod 把它逼出来的。

### 这个构建是**回写模式**（REPLACE=1）

也就是说它**真的会改数值** —— 检出坏掉的数就改成正常上限。这才是能生效的版本。
日志首行会写 `REPLACE=1  satfix-build-mode:write-back`。

> 影子模式（只看看、不改数值）是我们自己测试用的，不发布。
> 它对应 `satfix-build-mode:shadow`，首行 `REPLACE=0`。

## v0.3.0

修了三个后期存档里很烦人的毛病。都是同一件事引起的：mod 把数值堆得太高，游戏算着算着就"翻"了。

### 修了什么

- **护盾突然变成 0**。堆了一堆加成之后，护盾那一栏直接归零，看着像没护盾。
  实际是加成数字太大，游戏算崩了，自己又把结果当 0 处理。
  现在这种情况会改成游戏能表示的最大值 —— 显示成「92 万亿」，很大但至少不是 0。
  装甲理论上也会这样，不过我实测只有护盾触发，装甲一次都没误报。
  船体（舰船血量）也接了同样的处理，但船体那一栏在我测的存档里**从来没溢出过**，
  所以它只有「不会误伤」的实测记录，**没有「溢出时确实修好了」的实测记录**。
  理论上它是安全的（漏算的几项都是加法，只会让估算偏小，而封顶值是天定的那个上限），
  但既然没亲眼见过，就如实说一声。
- **舰船详情里的「伤害」变成负数**（或者大得离谱）。
  那一格是船上所有武器加起来、再乘射速加成。射速加成堆得太夸张时就会算爆。
  现在同样封顶到最大值。**这个只影响面板上显示的数字，不影响实际打出来的伤害** ——
  面板是临时算的，真打起来走的是另一套，不受影响。
- **过一天变慢**。这版把两个拖速度的地方优化了，实测每过一个游戏日明显变快。

### 这个构建是**回写模式**（REPLACE=1）

也就是说它**真的会改数值** —— 检出坏掉的数就改成正常上限。这才是能生效的版本。
日志首行会写 `REPLACE=1  satfix-build-mode:write-back`。

> 影子模式（只看看、不改数值）是我们自己测试用的，不发布。
> 它对应 `satfix-build-mode:shadow`，首行 `REPLACE=0`。

**会改动存档里的数值**，这本来就是它的作用。第一次用建议先备份存档。

改的时候很保守：**宁可漏掉，也不乱改**。只有游戏算出来的数本身就明显不对
（负数、或者明明该有值却是 0）才动手；正常数值哪怕我们内部算得有出入，也只记日志不改。

### 安装

启动器 → 插件 → 安装，或直接解压到
`Documents\Paradox Interactive\Stellaris\plugins\satfix\`。

适配 `stellaris.exe` 构建 `0x6ABEAA3F`（Cygnus v4.5.2）。游戏更新后会被自动跳过，
这是保护而非故障。

### 已知限制

- 只适配上面列出的构建；游戏更新后需要重新确证地址并升版本发布。
- **未与其他插件同时启用测试过**（本机只有 satfix 一个插件）。
- 部分目标只检出、不修改（观测模式），这是有意为之：判据不够硬的地方宁可不改。
- 「伤害」那一格修好后仍是「92 万亿游戏单位」这个上限值 —— 定点格式本身的物理天花板，
  继续往上堆加成只会再次越界。

详见仓库 [README](https://github.com/Aa728848/satfix)。

## v0.2.0

首个发布。Windows 侧 17 个目标实机验证全部装上，Linux 侧 19 个 hook 目标全部覆盖。

### 它做什么

把 Stellaris 的定点算术接上饱和处理。定点数用 `int64` 存、1.0 记作 `100000`，
上限约 9.2e13 游戏单位；mod 堆叠乘法越过之后**不报错**，直接 wrap 成负数 ——
海军容量变负、资源扣成天文数字、外交权重突然为负。

回写路径有端到端验证（同一构建脚本只差一个开关）：

| 构建 | `GetRounded(INT64_MAX)` 返回 |
|---|---|
| shadow | `-92233720368547`（游戏 wrap 后的值，就是那个 bug） |
| **write-back** | `+92233720368547`（**饱和值，被纠正了**） |

一局后期 mod 存档实测：2390 万次调用、0 条真实分歧
（原版量级离阈值差十几个数量级，要看到效果需要 mod 把数值推到 ~9.2e17）。

### 安装

启动器 → 插件 → 安装，或直接解压到
`Documents\Paradox Interactive\Stellaris\plugins\satfix\`。

适配 `stellaris.exe` 构建 `0x6ABEAA3F`（Cygnus v4.5.2）。
